🛠️ How This Web Application Works

This website is a hybrid application split into a Java Console Backend and a Vanilla Web Frontend. Here is where the components are located and what jobs they do:

1. The Backend processor: SortComparison.java

Location: Root folder. This is the compiled Java program you run from your terminal.
Its Job:

  • Asks you to type the size and numbers of your array in the console.
  • Performs the actual Quick Sort and Selection Sort logic entirely in Java.
  • Records every single comparison, swap, pivot selection, and minimum-index updates, along with the precise execution time in nanoseconds.
  • Exports all this recorded trace data into a JavaScript file called data.js.

2. The Frontend visualizer: index.html, style.css, script.js

Location: Root folder. These are the static web assets you view in the browser.
Their Job:

  • index.html loads the data.js file generated by Java.
  • script.js reads the array steps and animations from the data file.
  • Draws the side-by-side bar representations and animates them synchronously so you can watch both algorithms sort your custom array elements in real-time.

💼 The Real-World Jobs & Locations of the Algorithms

Different sorting algorithms are used in different places in industry depending on constraints like CPU speed, memory size, and hardware wear.

Selection Sort

Where it is added in industry:

Mainly used in Embedded Systems, microcontrollers, and hardware devices where memory is extremely small and write operations are physically damaging.

Its Real-World Job:

Since Selection Sort performs at most O(N) swaps (it only swaps when it finds the absolute minimum element), it is used when writing to memory is very expensive or slow (such as writing to EEPROM or Flash memory). It minimizes wear-and-tear on physical storage while sorting small datasets.

Quick Sort

Where it is added in industry:

Found in standard programming libraries (like Java's Arrays.sort() for primitive types), operating system kernels, databases, and general search algorithms.

Its Real-World Job:

Its job is to sort large volumes of data at maximum CPU speed. Because of its in-place design, it requires very little extra memory (only call-stack memory). It also exhibits great "cache locality," meaning the computer's CPU cache memory reads its elements extremely fast, outperforming other sorts like Heap Sort and Merge Sort in average real-world tasks.
